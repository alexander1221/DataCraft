# Редактирование графа в desktop

Поузловые кнопки ▶ / ⏩, подсветка и индикаторы: [NODE_EXECUTION.md](NODE_EXECUTION.md).

## §1. Задача

Собирать и менять локальные DAG из существующих 27 типов нод, не редактируя
JSON вручную. Все постоянные изменения выполняет Session; UI не имеет mutable
доступа к Project. Формат `.dcraft` остаётся v1.

## §2. Алгоритм

New project создаёт пустой проект через `project.new`. Палитра берёт типы,
названия и defaults из NodeSpec. Добавление использует новый UUID и typed draft
config. Удаление — RemoveNode (Session удаляет incident edges и designated output).
Инспектор строит поля по ParameterSpec, хранит локальный буфер и применяет его
одной ConfigureNode. Соединение: нажать выход, затем вход. Escape/правая кнопка
отменяют незавершённый жест. Существующие рёбра отключаются в инспекторе.

## §3. Применения

Создать CSV Source → Filter → Select Columns → Limit → Table Preview; задать
параметры, Save as, Run selected. Также можно открыть sample, изменить Filter,
добавить неполную ветку, удалить/вернуть ноду через Undo и сохранить черновик.

## §4. Контракт

Создание, удаление, Apply, Connect/Disconnect, назначение выхода — отдельные
undoable команды. New/Open/Save не добавляются в undo. New защищает dirty state
и активный job так же, как Open; сбрасывает path/history/результат предыдущего
проекта, увеличивает revision, новый проект dirty до первого Save as.
Строки/списки/Boolean/u32/finite f64 задаются типизированными полями. Ошибка
парсинга оставляет граф и историю неизменными. Семантически неполные значения
можно Apply и сохранить: readiness diagnostics показывают, что требует правки.
Неправильные порты, типы, дубликаты, занятый single input и цикл отвергает Session.

Неотправленный буфер не является Project state. Он учитывается при закрытии,
New/Open и смене выбранной ноды; есть явные Apply/Discard/Keep editing.
Save применяет текущий буфер; Run, Undo/Redo, добавление/удаление нод отключены,
пока буфер не применён или отменён. Ошибка Open не удаляет буфер и выбор.

## §5. Реализация

`editor.rs` — ParameterSpec-driven буфер/виджеты, `canvas.rs` — временный жест
портов и Action::Connect, `lib.rs` — Session adapter, палитра и защита переходов.
`project.new` регистрируется в engine с typed parameters и structured result/event.

## §6. Замечания

Временный провод и поля инспектора не сериализуются. Apply/Revert явно разделяют
редактирование и исполнение. Строковые списки редактируются по элементам, без
разделителей/экранирования: имя колонки с запятой сохраняется одним элементом.
Занятый вход требует Disconnect; скрытого замещения ребра нет.

## §7. Приёмка

Независимые тесты: разные типы параметров, ошибочное число/NaN, сохранение имени
колонки с запятой, незавершённый ввод при смене selection/Open, восстановление
узла с рёбрами через Undo, pointer events output→input и Escape без изменения
графа, отказ при цикле/несовместимых портах, New lifecycle и save/load черновика.
Результаты исполнения и native smoke фиксируются в VALIDATION.md.

## §8′. Устойчивость

Идентификаторы портов стабильны и берутся из NodeSpec. Невалидные действия
возвращают видимую ошибку; кандидат не становится частью графа. Файлы не
сохраняются автоматически. New/Open защищают также ещё не применённый буфер.
Внешний force-close ОС по-прежнему может потерять несохранённые изменения.
