# Читаемость графа и результата

## §1. Задача

Разнести ветки примеров, дать Arrange для открытого графа, отделить интервал
между колонками preview и перестать помечать результат устаревшим после Move/Rename.

## §2. Алгоритм

Две transient ревизии Session: project revision для всех persistent правок,
computation revision для изменения UUID/config/edges/designated output.
При Run сохраняются обе; результат сравнивается с computation revision снимка.
Move/Rename, Save и Save as с сохранением назначения sources не меняют её.
Undo/Redo параметров меняют её даже при восстановлении прежнего содержимого:
это консервативная политика, требуется повторный Run. Не связанные ветки также
инвалидируют результат. Изменения файлов с данными извне не отслеживаются.

Arrange группирует DAG по самому длинному пути от sources, упорядочивает соседей
по центрам родителей и UUID, разносит ноды по высоте с запасом. Размеры берутся
из тех же портов, что canvas. Все Move отправляются одним Batch через Session.
Estimator с единственным Model-выходом получает смещение вверх, чтобы отделить
обучение от table-потока. Голубые/золотые линии соответствуют Table/Model.
Preview использует явные межколоночные интервалы и min width ячеек.

## §3. Применения

Открыть ML-пример, Arrange, Run; переместить ноду — результат остаётся актуальным,
проект становится dirty, Undo восстанавливает раскладку. Поменять Filter —
результат требует нового Run. Save сохраняет новую геометрию как раньше.

## §4. Контракт

Arrange — явное действие с одним Undo; Open не меняет пользовательскую геометрию.
Кнопка находится слева, под Nodes. Model-связи золотые, Table-связи синие.
Алгоритм детерминирован, не зависит от исходных позиций/порядка nodes/edges.
Нет обещания минимального числа пересечений или ортогональной трассировки.
Примеры с fit/transform получают разнесённые ветки; sample.dcraft пользователя
не переписывается автоматически. AGENTS.md и protocol/project v1 не меняются.

## §5. Реализация

Состояние ревизий — только engine Session. Arrange — UI adapter над существующим
Batch/Move, без нового executor или UI зависимости в core/engine.

## §6. Ограничения

Раскладка эвристическая; фиксированный порядок портов может требовать пересечений.
Fit/zoom уменьшают большой граф, панорамирование и ручные правки доступны.

## §7. Проверка

Инварианты: отсутствие пересекающихся node rectangles, возрастание X по каждому
ребру, разнесение train/test, повторяемость и один Undo. Mouse/UI acceptance
проверяет видимый промежуток между id и отрицательным x. Проверяются Move/Rename
во время/после исполнения и реальная инвалидизация при Configure.

## §8′. Устойчивость

Некорректный DAG возвращает ошибку без частичного перемещения. Arrange не пишет
файл без Save. Результаты не переименовываются и не скрываются при layout edits.
Фактические проверки и ограничения среды записываются в VALIDATION.md.
