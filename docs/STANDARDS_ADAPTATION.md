# Адаптация пользовательских стандартов

Дата: 2026-11-08. Источник: `code-generation-standards_v4.zip`,
entry point `code-generation-standards/SKILL.md`. Исходный архив и AGENTS.md
не изменялись. Готовая папка навыка: `skills/datacraft-code-standards/`.

## Что сохранено

- Самодостаточная документация в порядке §1–§8; §8′ для нечисленных модулей.
- Независимые оракулы, свойства/приёмка и обоснование численных допусков.
- Уровни эквивалентности bitwise / ulp / bound для численных переписок.
- Проверка всех внешних зависимостей, разделение публикации и устанавливаемости.
- Реестр verified / ASSUMPTION и честные статусы PASS / FAIL / NOT_RUN.
- Windows encoding boundaries, ASCII setup scripts, Unicode data, UTF-16
  бюджет путей, CRC/UTF-8 flags и проверка настоящим потребителем ZIP.
- Ворота G1–G9 с независимой приёмкой для изменений высокого риска.

## Что адаптировано

| Исходный Python workflow | DataCraft |
|---|---|
| pip, requirements, wheels, venv | Cargo manifests/lock, sbt, Maven, JDK/linker |
| pytest, Python AST/ruff | Rust tests/check/Clippy, Scala MUnit/compile/test |
| Python exceptions | Result/structured worker errors; exceptions в helpers |
| verify_install | actual tool versions + реальный CLI/Spark smoke scenario |
| numpy equivalence helper | аналитические оракулы и backend-specific численные контракты |

Python остаётся необязательным developer-инструментом; у DataCraft runtime
новой зависимости от Python нет. Helper проверяет только перечисленные
статические свойства, без сети и запуска кода проекта.

Документация допускает companion Markdown для модуля и реестр внешних фактов
в одном месте. Восемь секций не копируются в каждый accessor. Формальный
200-unit path budget сохранён как политика поставки, а не обещание поддержки
любой глубины Windows-пути. Для byte-reproducible ZIP нужны также timestamps
и permissions, не только сортировка entries.

Исходные скрипты check_external/equivalence_check не скопированы: их Python
wheel/numpy-проверки не верифицируют Cargo/Maven/Spark. ZIP helper не переносился
без пересмотра исключений Cargo workspace и обработки symlinks. История
инцидентов и внешние утверждения старого навыка не скопированы как новые факты.

## Использование

В текущем сеансе навык читается по явному пути:

```text
Применяй skills/datacraft-code-standards/SKILL.md к изменениям DataCraft.
```

Для автоматического обнаружения перенесите целую папку datacraft-code-standards
в `.agents/skills/` проекта. В текущей сессии запись в `.agents` отклонена
автоматической проверкой доступа, поэтому подготовлена доступная папка skills.
Факт создания папки skills сам по себе не означает автоматического подключения.
При переносе поправьте путь команды developer-валидатора либо запускайте его
по новому расположению. References используют переносимые относительные ссылки.

## Проверки этой адаптации

- Helper самотестирование: 8 тестов, 7 PASS, 1 SKIP. Case-collision test
  пропущен на case-insensitive filesystem; NFC-collision test выполнен.
- Helper по репозиторию: 0 ошибок статических проверок. Это не Rust/Scala build,
  не YAML parser и не сетевой аудит зависимостей.
- Entry point: отдельно проверены обязательные name/description, соответствие
  имени папке и существование всех локальных Markdown-ссылок.
- Штатный skill-creator quick_validate.py: не запустился; отсутствует модуль
  PyYAML. Его проверка не считается пройденной; helper его не подменяет.
- Независимая поведенческая приёмка навыка отдельным reviewer не проводилась.
  Этот отчёт не сертифицирует качество всех решений будущего агента.
