# Самодостаточная документация

Это пользовательская адаптация практики Wilkinson/Reinsch, а не приписываемый
им дословный стандарт. Сохранён порядок исходного навыка.

## §1. Постановка задачи

Для численного модуля задайте математические входы, выходы, цель и ограничения.
Для DAG, файла проекта или протокола опишите сущности и инварианты без
искусственной математики. Например: обязательные входы соединены ровно один
раз, ребро связывает существующие совместимые порты, циклы запрещены.

## §2. Алгоритм

Объясните последовательность действий, промежуточные объекты и завершение.
Для топологической сортировки укажите правило разрешения равенства UUID;
для worker — планирование зависимостей, границы materialization и ошибки.
Для estimator укажите fit/transform, критерии остановки и backend.

## §3. Применения

Перечислите пользовательские сценарии, следующие из контракта. Каждый должен
иметь проверяемый приёмочный пример: открыть проект, выполнить выбранный
выход, получить ограниченный preview, применить обученную модель.

## §4. Спецификация

Опишите типы, диапазоны, defaults, единицы, nullability и изменение данных.
Для ноды: стабильный kind, порты/cardinality, параметры, допустимые схемы,
результаты, файлы и ошибки. Для протокола: версия, UUID, framing, кодировка,
лимиты, поведение при ошибке/отмене и lifecycle состояния.
Для численной миграции добавьте эталон, версию и уровень эквивалентности.

## §5. Реализация

Используйте ссылки на реальные Rust/Scala symbols и файлы. Комментарии
объясняют инварианты, математику и нетривиальные решения. Не дублируйте
исходники целиком в документации и не комментируйте очевидный синтаксис.

## §6. Замечания

Документируйте владение, потоки, объём памяти, ленивость DataFrame, Spark actions,
кэширование, освобождение worker и файлов. Limit перед collect ограничивает
строки результата, но не гарантирует ограниченную память всего плана.

## §7. Примеры и проверка

Укажите вход, независимый оракул, команду и фактический результат запуска.
Для неисполненного примера пишите «ожидается; NOT_RUN», не выдумывайте вывод.
Фиксируйте граничные случаи, ошибки и восстановление после ошибки.
Свойства: round-trip, независимость порядка nodes/edges, детерминированный
выбор доступных UUID, сохранение версии/координат, ограничение preview.

## §8. Ошибки вычислений / §8′. Устойчивость

Для численных процедур объясните каждый допуск, обусловленность, solver,
NaN/Inf и диапазон применимости оценки. Для остальных — невалидный ввод,
ресурсные ограничения, сложность, переполнение, частичная запись,
несовместимая версия, сбой процесса и восстановление.

Восемь секций могут находиться в `//!`, Scaladoc либо companion Markdown,
связанном с модулем. Сначала пишите §1–§4, затем дополняйте документ.
Мелкая правка документа не требует нового восьмисекционного документа,
но обязана сохранять контракт.
