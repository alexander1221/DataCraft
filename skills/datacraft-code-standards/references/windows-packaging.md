# Windows, кодировки и поставка

## Кодировки

- .ps1, .bat, .cmd и сообщения developer-setup helpers пишите в ASCII
  для совместимости с Windows PowerShell 5.1 и cmd. Это политика проекта,
  а не утверждение, что Windows вообще не поддерживает Unicode.
- Rust, Scala, Markdown, .dcraft и протокол worker — UTF-8. ASCII-ограничение
  setup не распространяется на пользовательские данные/имена колонок.
- Проверяйте кириллицу, пробелы и Unicode в путях через настоящий CLI/worker.
  Не исправляйте кодировки транслитерацией или потерей данных.
- Во вспомогательном Python выводите ASCII-safe диагностику; временно меняя
  console encoding/PYTHONIOENCODING, восстанавливайте состояние в finally.
  Не меняйте глобально code page или ExecutionPolicy.
- Запускайте процессы массивом аргументов; не собирайте shell-команду из
  dataset paths. Native exit code проверяйте явно: ErrorAction не заменяет
  проверку $LASTEXITCODE.

## Пути

Избегайте Windows reserved names, trailing dot/space, управляющих символов,
конфликтов регистра и NFC-нормализации. Сравнивайте полный относительный путь,
включая каталоги. При упаковке приводите имена к NFC с обнаружением коллизий;
в существующем проекте не переименовывайте их молча.

200 UTF-16 code units на относительный путь — пользовательский бюджет поставки
для архива, а не универсальный лимит Windows. Учитывается префикс распаковки;
глубокий OneDrive-путь может превысить запас. Кэши Cargo/Maven и runtime temp
paths этим бюджетом автоматически не покрываются.

## ZIP, только когда запрошена поставка архивом

1. Формируйте staging tree из явного состава поставки. Не включайте .git,
   target, toolchain caches, секреты и персональные данные. Исходный ZIP
   стандартов также не входит в release без отдельной причины.
2. Архив назначения держите вне staging tree; откажитесь от обхода symlink
   за пределы дерева. Не извлекайте чужие архивы без проверки traversal,
   абсолютных путей, symlink и размеров распаковки.
3. Записывайте детерминированный порядок записей; для воспроизводимости байтов
   дополнительно фиксируйте timestamps/permissions, не только сортировку.
4. После сборки проверьте CRC, имена/коллизии, бюджет путей и UTF-8 bit 0x800
   у всех не-ASCII имён. ASCII-имена не требуют этого флага.
5. Проверьте распаковку и запуск у реального потребителя. Проверка ZIP библиотекой
   не доказывает совместимость с Проводником или успешную работу приложения.
6. Публикуйте архив после проверки временного результата; частичный файл
   не считается готовым артефактом.

Исходный zip_windows_safe.py не перенесён: его exclusions и symlink policy
нужно адаптировать перед использованием с Cargo workspace. Новый packager
не требуется до задачи на поставку ZIP.

Для скачанного доверенного архива при необходимости объясните Unblock-File
для конкретного проверенного файла. Не разблокируйте рекурсивно чужие файлы
и не отключайте системные защиты ради setup.
